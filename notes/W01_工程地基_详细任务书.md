### 2.3 ⏳ 现在做：把 WSL 迁到 D 盘（核心步骤）

**目的（为什么必须做，以及为什么必须现在做）**

WSL 里的整个 Linux 系统，在 Windows 眼里就是**一个虚拟磁盘文件**（`ext4.vhdx`），默认躺在 `C:\Users\cc\AppData\Local\Packages\…\LocalState\` 里。它有两个特性决定了这件事不能拖：

1. **只增不减**：往 Linux 里写多少东西，它就长多大；以后你即使删掉文件，这个文件也不会自动缩回去。
2. **后面要装的全是大块头**：PyTorch 约 3GB、conda 环境和各种库 3-5GB、数据集几 GB 到几十 GB、HuggingFace 模型缓存动辄几十 GB——**它们全都落在这个文件里**。

你 C 盘只剩 108GB，D 盘剩 194GB。现在里面只有 2GB 左右，搬一次几分钟；等装完上面那些再搬，就是几十 GB 的搬家。**这是整条路线里唯一一个"越晚做代价越高"的操作**，所以今天优先做掉。

**操作（在 PowerShell 里执行，不是 Ubuntu 里）**

```powershell
wsl --shutdown
wsl --manage Ubuntu-22.04 --move D:\wsl\Ubuntu-22.04
```

`wsl --shutdown` 的作用是**先把所有正在运行的 Linux 实例停掉**——文件正在被占用时是没法移动的。执行完等十几秒再跑第二条。

> 如果第二条报错说参数无效（不认识 `--move`），用下面这套备选方案，效果一样，只是多几步：
>
> ```powershell
> wsl --shutdown
> mkdir D:\wsl
> wsl --export Ubuntu-22.04 D:\wsl\ubuntu.tar
> wsl --unregister Ubuntu-22.04
> wsl --import Ubuntu-22.04 D:\wsl\Ubuntu-22.04 D:\wsl\ubuntu.tar --version 2
> del D:\wsl\ubuntu.tar
> ```
>
> **用备选方案必须补这一步**：`--import` 之后默认用户会变成 `root`，要恢复成 `cc`。进入 Ubuntu 后创建 `/etc/wsl.conf`：
>
> ```ini
> [user]
> default=cc
> ```
>
> 然后回 PowerShell 执行 `wsl --shutdown`，再进来提示符就恢复成 `cc@Sahara` 了。

**坑**

- 迁移过程中**不要关机、不要断电**。整个操作本质是移动一个大文件。
- 目标目录不用你手动创建，WSL 会自己建；如果它报错说目录已存在，就把那个空目录删掉再重试。
- 迁移完成后发行版名字不变（还是 `Ubuntu-22.04`），所以 Windows Terminal 里你刚配的那个"启动目录 `~`"继续有效，不用重配。

**验证（4 条全过才算完成）**

- [ ] `D:\wsl\Ubuntu-22.04\ext4.vhdx` 这个文件存在

### 2.4 建工作目录 + 装 Linux 基础工具

**目的**

- **`~/projects`**：这是你以后放所有代码的地方。为什么不放 `/mnt/c`？因为在 Windows 盘上读写文件，Linux 每次都要经过一层格式转换，实测慢 5-10 倍；小文件一多（比如一个 Python 项目成千上万个文件），会慢到让你误以为是代码写错了。
- **`apt install` 那一串工具**：`apt` 是 Ubuntu 的包管理器，装的是**系统级工具**，和后面用 `pip` 装的 Python 库属于两个层面。每一个后面都会用到：

| 工具 | 什么时候会用到 |
|---|---|
| `build-essential`（gcc/g++/make） | 有些 Python 包没有现成的轮子，必须现场编译源码 |
| `git` | 版本控制，Day 5 的主角 |
| `wget` / `curl` | 下载数据集、模型权重、安装脚本 |
| `vim` | 终端里的编辑器。服务器上没有图形界面，改配置文件只能靠它 |
| `htop` | 看 CPU 和内存占用，比自带的 `top` 直观 |
| `tmux` | **关键**：会话保持，Day 4 的主角，训练任务能不能活过 SSH 断开全靠它 |
| `unzip` | 解压下载的数据集 |

**操作**

```bash
# 建工作目录（以后所有代码都放这里）
mkdir -p ~/projects && cd ~/projects

# 更新软件源并安装基础工具
sudo apt update && sudo apt install -y build-essential git wget curl vim htop tmux unzip
```

`sudo` 会要求你输入密码——**输入时屏幕不会有任何显示**，这是正常现象，输完直接回车。`apt update` 是"刷新软件商店的目录"，`apt install` 才是真正安装，所以两条要连着执行。

**验证**

```bash
git --version
tmux -V
gcc --version
```

三条都有版本号输出即通过。

**坑**：apt 在国内可能比较慢（默认源在国外）。如果 `apt update` 卡着不动或速度只有几十 KB/s，先告诉我，我给你换成国内镜像源，两行命令的事。

## 3. Day 2（10/1）：Miniconda + PyTorch

**目的（为什么必须用 conda，而不是直接用系统 Python）**

Ubuntu 自带一个 Python，但那是**给操作系统自己用的**：你用 `pip install` 往里面装东西，轻则把系统工具搞坏，重则整个系统命令起不来（Ubuntu 的很多系统脚本依赖它）。conda 解决的就是这件事——它给每个项目开一个**独立的盒子**，盒子里有自己的 Python 和库，互相不打架。你以后会同时有好几个项目，需要不同版本的 PyTorch，靠的就是这个机制。

`conda init bash` 的作用是把 conda 写进 `~/.bashrc`（终端启动时自动执行的配置文件），这样你每次打开终端都能直接用 `conda` 命令，不用敲一长串路径。

```bash
# 1) 装 Miniconda
wget https://repo.anaconda.com/miniconda/Miniconda3-latest-Linux-x86_64.sh -O ~/miniconda.sh
bash ~/miniconda.sh -b -p $HOME/miniconda3
~/miniconda3/bin/conda init bash
source ~/.bashrc

# 2) 建环境（以后所有项目都用这个环境，别在 base 里装东西）
conda create -n llm python=3.11 -y
conda activate llm

# 3) 用国内镜像加速 pip（PyTorch 的 wheel 有 2-3GB，走官方源可能几十分钟甚至断线）
pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple

# 4) 装 PyTorch（Linux 下从 PyPI 装的 torch 自带 CUDA 运行时）
pip install torch torchvision torchaudio
# 如果上面装成了 CPU 版，用官方源指定 CUDA 版本重装：
# pip install torch torchvision --index-url https://download.pytorch.org/whl/cu124

# 5) 常用库
pip install numpy pandas matplotlib jupyter scikit-learn tqdm
```

**验证三连（必须全部通过）**

```bash
nvidia-smi                                                    # 能看到 RTX 3060 Laptop
python -c "import torch; print(torch.__version__, torch.version.cuda)"
python -c "import torch; print(torch.cuda.is_available(), torch.cuda.get_device_name(0))"
```

### 必须搞懂的 3 个概念

| 概念 | 你要能解释清楚 |
|---|---|
| 驱动 / CUDA Runtime / cuDNN 的区别 | `nvidia-smi` 里的 "CUDA Version 12.7" 是**驱动支持的最高版本**，不是你装了的版本；PyTorch 自带 CUDA Runtime，所以不用单独装 CUDA Toolkit |
| 为什么用 conda 环境 | 隔离依赖，避免"装了一个库把另一个项目搞坏"；每个项目一个环境 |
| `torch.cuda.is_available()` 为 False 的排查顺序 | ① 装成 CPU 版了（`torch.version.cuda` 是 None）→ ② WSL 里 nvidia-smi 不通 → ③ Windows 驱动太旧 |

**本周最后要做的实战**：把 day02 的 `05_手写数字识别案例.py` 在新环境里跑起来（需要 `pandas`、`matplotlib`）。跑通 = 环境合格。

## 4. Day 3（10/2）：Linux 命令（只学"训练会用到"的）

**目的**：这些命令不是为了"学 Linux"而学，而是**为了在服务器上跑实验不被卡住**。你以后的工作状态是：SSH 连上一台没有图形界面的机器，把代码传上去，把训练挂到后台，然后不停地看日志、看显存、看进程。下面这些就是那套动作的最小集合。**不要背命令大全，只练"看日志、挂后台、查资源"三件事。**

### 4.1 文件与目录

```bash
ls -lh            # 带大小、易读
ls -lhtr          # 按时间倒序，看最新产物
pwd / cd / mkdir -p a/b/c
cp -r src dst     # 复制目录
mv a b            # 重命名/移动
find . -name "*.py" -type f
wc -l train.py
```

⚠️ `rm -rf` 是**不可恢复**的，执行前先用 `ls` 确认目标路径，永远不要对 `/`、`~`、`*` 直接下手。

### 4.2 看文件（看训练日志必备）

```bash
cat log.txt
head -n 20 log.txt
tail -n 50 log.txt
tail -f log.txt              # 实时跟踪日志，最常用
less big_file.txt            # 按 / 搜索，G 跳末尾，q 退出
grep -rn "loss" .            # 递归搜索
grep -c "ERROR" log.txt      # 计数
```

### 4.3 权限

```bash
chmod +x run.sh              # 让脚本可执行
ls -l                        # 看懂 -rwxr-xr-x 每一段的含义
```

### 4.4 进程与资源（每天都用）

```bash
ps aux | grep python         # 找自己的进程
top / htop                   # 看 CPU 和内存
nvidia-smi                   # 看显存和 GPU 利用率
watch -n 1 nvidia-smi        # 每秒刷新一次
kill -9 <PID>                # 强杀（先用普通 kill）
```

### 4.5 管道与重定向 ★ 本周最重要的知识点

```bash
python train.py > log.txt 2>&1          # 标准输出和错误都写进日志
nohup python train.py > log.txt 2>&1 &  # 后台运行，断开 SSH 也不中断
```

你必须能解释：`>` 和 `>>` 的区别、`2>&1` 为什么必须有、`&` 和 `nohup` 各自解决什么问题。

> ⚠️ **WSL 专属注意事项（9/30 实测踩到）**
>
> `nohup` 保护的范围是"**终端会话断开**"，**不是**"整台机器关机"。而在 WSL 里，**关掉最后一个终端窗口 = 把整台 Linux 关掉**——发行版会被关闭，里面所有进程（包括 `nohup` 起来的、`tmux` 里的）一起被杀。
>
> 实测证据：关窗口时脚本停在 `epoch 3`（约 15:17:30），重新打开后 `uptime` 显示 `up 14 min`（即 15:20 才启动）→ 说明关窗口那一刻整个发行版就关了。
>
> 结论：
> - 在**真服务器 / 实验室机器 / 云 GPU** 上（永远开机），`nohup` 和 `tmux` 是标准做法，这个技能必须掌握。
> - 在 **WSL 里**要让长任务活过关窗口，只有两条路：① 留一个 WSL 窗口开着（最小化即可）；② 从 Windows 侧用隐藏进程启动（见 5.4）。

## 5. Day 4（10/3）：远程与长任务（这是你以后在服务器上吃饭的技能）

**目的**：训练不是跑 3 分钟就结束的——一个实验动辄几小时甚至几天，而你不可能一直守在电脑前。这一节要解决的核心问题是：**如何让任务在你关掉终端、合上笔记本、断开网络之后仍然继续跑，并且随时能看到进度。** 这是区分"会写模型的人"和"能跑实验的人"的地方。

### 5.1 tmux —— 会话保持

```bash
tmux new -s train        # 新建名为 train 的会话
# 在里面启动训练……
# 按 Ctrl+B 然后按 D        → 脱离会话（训练继续跑）
tmux ls                  # 列出所有会话
tmux attach -t train     # 重新接入
tmux kill-session -t train
```

**为什么要学**：笔记本合盖、网络抖动、SSH 断开都会杀死前台任务。tmux 是实验能跑一整晚的前提。

### 5.2 传文件

```bash
scp model.pkl user@server:/data/xxx/          # 单文件
rsync -avz --progress ./data/ user@server:/data/xxx/   # 目录，支持断点续传
tar -zcvf data.tar.gz data/                   # 打包
tar -zxvf data.tar.gz                         # 解包
```

### 5.3 磁盘（数据集塞满盘是经典事故）

```bash
df -h                    # 整体剩余空间
du -sh *                 # 当前目录下每项占多大
du -sh ~/.cache/huggingface   # HF 模型缓存，往往是元凶
```

### Day 4 实战任务（本周的核心验收之一）

写一个"假装训练 10 分钟"的脚本，然后用 tmux + nohup 两种方式挂到后台，日志能实时看到，关掉终端再回来任务还在跑。

```bash
cat > ~/practice/fake_train.py <<'EOF'
import time, random
for epoch in range(1, 61):
    print(f"epoch {epoch} loss {random.random():.4f}", flush=True)
    time.sleep(5)
EOF

cd ~/practice
nohup python fake_train.py > fake.log 2>&1 &
tail -f fake.log
```

> 注意 `flush=True`：不加它，Python 会缓冲输出，你会误以为程序卡死了。这是新手最常见的"假死"困惑。

### 5.4 补充：在 WSL 里让长任务活过关窗口

如果你不想一直开着一个终端窗口，可以从 **Windows 侧**用一个隐藏进程把任务启动起来。原理是：这个隐藏的 `wsl.exe` 进程只要还在运行，就等于一直"占着"WSL 发行版，发行版就不会被关闭，里面的任务自然也就活下来了。

在 **PowerShell** 里执行：

```powershell
Start-Process -WindowStyle Hidden wsl.exe -ArgumentList '-d','Ubuntu-22.04','--','bash','-lc','cd ~/day03 && python fake_train.py > fake3.log 2>&1'
```

要停止它，就在 WSL 里找到进程再杀掉：

```bash
ps aux | grep fake_train | grep -v grep
kill <PID>
```

**两种方式的取舍**

| 方式 | 优点 | 缺点 |
|---|---|---|
| 留一个 WSL 窗口开着（最小化） | 简单，随时能看到输出 | 桌面上多一个窗口 |
| 隐藏进程启动 | 桌面上干干净净 | 看不到实时输出，只能翻日志 |

> 补充：即使这样，**关掉电脑 / 让笔记本休眠**依然会中断任务——这一点在真服务器上不存在，因为服务器永远开机。这也是为什么大模型训练最终一定要放到服务器上跑，而不是靠笔记本。

## 6. Day 5（10/4）：Git 与 GitHub

**目的**：三个理由。① **可回退**：实验里改了十版代码，某一版结果最好，没有 Git 你只能靠复制文件夹；② **简历**：实习面试官真的会翻你的 GitHub，仓库质量比你说什么都有说服力；③ **协作**：进了公司第一天就要提交 PR，不会 Git 等于寸步难行。而这一节真正的高价值内容是**"什么东西绝对不能提交"**——你的 `day02` 里正好有一个 201MB 的 `.pkl` 当教材。

### 6.1 初始配置与 SSH

```bash

ssh -T git@github.com                    # 出现 "Hi xxx! You've successfully authenticated" 即成功
```

### 6.2 必须掌握的工作流

```bash

git push -u origin main
git pull
```

commit message 用前缀：`feat:` 新功能 / `fix:` 修 bug / `docs:` 文档 / `refactor:` 重构。

### 6.3 ★ 本周最值钱的知识点：什么东西绝对不能进 Git

我先看了你的 `day02` 目录，现状是这样的：

| 文件 | 大小 | 能提交吗 |
|---|---|---|
| `model/手写数字识别.pkl` | **201 MB** | ❌ 绝对不能 |
| `data/手写数字识别.csv` | **73 MB** | ❌ 绝对不能 |
| `*.py` 源码 | 几 KB | ✅ 应该提交 |

而且 `day02` 现在还没建仓库、也没有 `.gitignore`。如果你直接 `git init && git add . && git commit`，会发生三件坏事：

1. GitHub 单文件超过 100MB 会**直接拒绝推送**，你会在 push 时才卡住。
2. 超过 50MB 会持续警告，仓库 clone 速度变成几分钟。
3. **大文件一旦进入 commit 历史，即使后来删掉文件，历史里仍然存在**，清理需要 `git filter-repo` 重写历史，非常麻烦。

正确做法：**数据和大文件一律用 `.gitignore` 排除，用"下载脚本 + 说明"代替**。需要版本管理大文件时才用 Git LFS。

`.gitignore` 模板（可以直接用）：

```gitignore
.ipynb_checkpoints/
.venv/

*.egg-info/

# 编辑器与系统

```


## 7. Day 6（10/5）：numpy 内功（后面写 attention 的地基）

**目的**：这是 W5"从零写 GPT"的地基。attention 的全部运算就是 `softmax(Q @ K.T / sqrt(d)) @ V`——没有任何魔法，就是几个矩阵乘法加一个 softmax。同样的，反向传播不理解，后面所有"为什么 loss 不下降""为什么梯度爆炸"你都无从下手。**今天写的每一行，两周后都会原样再用一遍。**

看起来基础，但 W5 从零写 GPT 时，attention 的全部运算就是 `softmax(Q @ K.T / sqrt(d)) @ V`——全是下面这些操作。

### 7.1 必须掌握的操作

```python
import numpy as np

x = np.arange(24).reshape(2, 3, 4)     # 形状与轴
x.shape, x.ndim, x.dtype
x.reshape(-1), x.transpose(0, 2, 1), x.reshape(2, -1)

# 广播：从右往左对齐维度，维度为 1 或缺失才能广播
a = np.zeros((8, 1)) + np.zeros((1, 5))   # → (8, 5)  ← 会生成 40 个元素，小心显存

# 聚合与取值
x.sum(axis=-1), x.mean(axis=0), x.max(axis=-1, keepdims=True), x.argmax(axis=-1)

# 索引
x[x > 10]                 # 布尔掩码
x[..., None]              # 等价 np.newaxis，插一个长度 1 的维度

# 随机与复现（实验可复现的基础）
rng = np.random.default_rng(42)
rng.normal(size=(3, 3))
```

### 7.2 必须手写的三个函数（不许抄）

```python
import numpy as np

def softmax(x, axis=-1):
    """数值稳定版：先减最大值，防止 exp 溢出"""
    x = x - x.max(axis=axis, keepdims=True)
    e = np.exp(x)
    return e / e.sum(axis=axis, keepdims=True)

def cross_entropy(logits, labels):
    """labels 是整数下标；用 log-sum-exp 避免 log(0)"""
    logits = logits - logits.max(axis=1, keepdims=True)
    log_probs = logits - np.log(np.exp(logits).sum(axis=1, keepdims=True))
    return -log_probs[np.arange(len(labels)), labels].mean()

def relu(x):
    return np.maximum(x, 0)
```

写完必须自测：

```python
x = np.array([[1000.0, 1001.0, 1002.0]])
print(softmax(x))          # 不减最大值会得到 nan/inf
```

### 7.3 手写两层网络的反向传播

这是 W2 的前置：用纯 numpy 实现 `Linear → ReLU → Linear → softmax`，手动推导并写出每一层的梯度，用 MNIST 数据训练，loss 要能下降。

```python
def init_params(in_dim, hidden, out_dim, rng):
    return {
        "W1": rng.normal(0, 0.01, (in_dim, hidden)), "b1": np.zeros(hidden),
        "W2": rng.normal(0, 0.01, (hidden, out_dim)), "b2": np.zeros(out_dim),
    }
```

推导时把每一步的张量形状写在旁边（`(B, 784) @ (784, 128) -> (B, 128)`），这是排查维度错误最有效的方法。

## 9. 常见坑（提前告诉你，省时间）

1. **在 WSL 里装显卡驱动** → 环境直接坏掉，重装 WSL。不要把 Windows 驱动装进 Linux。
2. **用 `sudo pip install`** → 把系统 Python 搞乱。永远在 conda 环境里用普通 `pip install`。
3. **训练任务用前台跑** → SSH 一断全没了。永远 `tmux` + `nohup`。
4. **Python 输出没加 `flush=True`** → 日志不实时，误判卡死。
5. **`git add .` 一把梭** → 把 201MB 的模型文件提交进去。先写 `.gitignore`，再 `git add`。
6. **在 `base` 环境装一堆库** → 后面项目互相污染。一个项目一个环境。
7. **C 盘装爆** → WSL 虚拟磁盘和 HF 模型缓存都在 C 盘，按 Day 1 的步骤迁到 D 盘。
8. **只收藏不敲** → 本周所有命令至少手动执行过一遍，抄来的命令记不住。
